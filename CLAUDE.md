# CharmOS

Своя ОС: x86-64, UEFI, freestanding C++23, гибридное ядро с капабилити,
драйверы в юзерспейсе. Цель — реальная система; сначала всё в QEMU.

## Текущая фаза

**M9 — ACPI AML и выход на реальное железо.** M0–M8.5 закрыты. Обновлять эту строку при переходе.

## Что читать

| Когда | Файл |
|---|---|
| Всегда, перед любой задачей | `plans/ROADMAP.md` — порядок фаз и критерии готовности (главный документ) |
| Куда класть код | `plans/LAYOUT.md` |
| Драйверы, PCI, IOMMU, DMA, профили | `plans/DRIVERS.md` |
| Ядро, IPC, GUI, принятые решения | `plans/os-gui-design.md` (журнал решений — в конце) |
| Любой интерфейс через границу | `docs/abi/*.md` |

При расхождении документов прав `ROADMAP.md`.

## Команды

Всё запускается в WSL2 (Ubuntu), не в PowerShell.

```bash
bash tools/setup-wsl.sh                           # один раз: тулчейн в Ubuntu
cmake -S . -B build -G Ninja && ninja -C build   # сборка (build/uefi, kernel, user, host)
tools/run.sh                                      # запуск в QEMU/OVMF, serial в stdout
tools/run.sh --gdb                                # с gdb-стабом на :1234
tools/test.sh <фаза>                              # QEMU-тесты фазы, exit code = результат
ctest --test-dir build/host --output-on-failure   # хост-тесты
```

Из PowerShell/Git Bash: `wsl -d Ubuntu --cd /mnt/a/CharmOS -- <команда>`.
Протокол теста: serial-вывод сверяется с `tests/qemu/<фаза>/*.expected`
(строки по порядку), QEMU должен выйти с кодом 33 (`isa-debug-exit` 0x10).

## Жёсткие правила

1. **Не писать код фазы, которая ещё не наступила.** Сказать об этом и остановиться.
2. **Готово = `tools/test.sh` зелёный.** Код, который не прогнан, не сделан.
3. **ABI стабилен.** Любой интерфейс между boot/kernel/user/драйверами сначала
   описывается в `docs/abi/` и согласуется с автором, потом реализуется.
   Изменения — только новой версией. Молча не менять.
4. **Спека перед кодом.** Регистры и структуры — только по документу из
   `docs/specs/`. Нет спеки — остановиться и сказать, не угадывать.
5. **Весь код свой.** Никаких сторонних библиотек (ACPICA, lwIP, mlibc, Limine…),
   утёкших исходников и декомпиляции. Исключения — только M11 и M14.
6. **C++ в ядре:** C++23, без исключений и RTTI, без нетривиальных глобальных
   конструкторов (`constinit`), все аллокации возвращают `Result`, `operator new`
   без проверки запрещён. Виртуальные функции и freestanding-заголовки std — можно.
7. **x86-специфика — только в `arch/x86_64/`.**
8. Структуры, разделяемые с железом или через ABI, — `static_assert` на размер и
   смещения. MMIO и DMA — с явными барьерами.
9. Никакой оптимизации до замера.
10. Решение, которое меняет архитектуру, не принимать молча: спросить автора,
    после согласования записать в журнал решений `plans/os-gui-design.md`.
11. При неуверенности — спросить, а не угадать.
