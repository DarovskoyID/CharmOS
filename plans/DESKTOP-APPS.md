## ИИ в универсальном доступе

Запрос владельца 2026-10-17: выбор провайдера и ввод собственного ключа в
настройках, затем запрос обычным языком и выполнение действий в CharmOS.
Не требовать передачи ключа разработчику или ввода его в чат.

Порядок реализации: HTTPS с проверкой сертификатов и времени; отдельный
процесс провайдера; скрытое поле ключа и явное удаление ключа; общий цикл
запрос → структурированный вызов инструмента → результат → ответ модели.
Первый вариант хранит ключ только в памяти сеанса. Постоянное хранение
добавлять через защищённое хранилище, отдельно от обычных desktop preferences.
Ключи и Authorization не попадают в serial, логи, снимки или crash reports.

Действия модели проходят общий проверяемый диспетчер: список приложений,
запуск известного приложения, открытие явно выбранного файла, вычисление,
изменение конкретной разрешённой настройки. Каждое действие проверяет
параметры, права сеанса и доступные capability. Текст ответа не исполняется
как shell. Запись/удаление файлов и установка пакетов требуют отдельного
разрешения пользователя с конкретными целями; обычное открытие приложения
не должно вызывать постоянные подтверждения. Предусмотреть остановку,
лимит шагов/ответа, тайм-аут, ошибки ключа, квоты и недоступную сеть.
Файлы и содержимое экрана не отправлять провайдеру автоматически.

Адаптеры: OpenAI Responses с function calling; Anthropic Messages с
tool_use/tool_result; Яндекс через официальный AI Studio API. У Яндекса
проверять необходимые идентификаторы ресурса/модели и доступ аккаунта:
подписка в приложении Алисы сама по себе не доказывает доступ к API.
Модель задаётся в настройках, без зашитого обещания доступности конкретной.

Контракт первой версии инструментов (внутренний, не syscall ABI):

| Инструмент | Аргументы | Действие |
|---|---|---|
| list_apps | отсутствуют | Только установленные приложения и их стабильные ID |
| launch_app | app_id из list_apps | Запуск с обычными правами приложения, без аргументов shell |
| calculate | expression | Общее ограниченное математическое ядро CharmOS |
| open_file | file_id из выбора пользователя | Только ранее выбранный файл, без доступа к произвольному пути |
| set_desktop_setting | setting: shadows/warm/russian, enabled: bool | Явно установить значение; повторный вызов не переключает его обратно |

Каждый вызов имеет ID; повторная доставка одного ID возвращает сохранённый
результат, а не повторяет действие. Неизвестный инструмент или лишние поля —
ошибка. Начальные лимиты: 8 действий на запрос, один выполняемый запрос,
64 КиБ ответа провайдера; отмена запрещает запуск новых действий. Ошибки
возвращаются модели без секретов. Увеличение прав через ответ модели невозможно.

Источники: [OpenAI](https://developers.openai.com/api/docs/guides/function-calling),
[Anthropic](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls),
[Яндекс: аутентификация](https://aistudio.yandex.ru/en/docs/ai-studio/api-ref/authentication).

Проверки: локальный тестовый провайдер для успешных и ошибочных ответов,
неизвестных инструментов и некорректных параметров; отмена запроса, повторные
вызовы, исчерпание лимита; отсутствие ключа в логах и файлах. Затем реальный
запрос каждого настроенного провайдера и снимок результата действия в QEMU.
Без настоящего API-запроса не объявлять интеграцию завершённой.

## Порт Chromium

Прямая сборка Linux-версии не является портом на собственное ядро. Нужны
поддерживаемый toolchain/sysroot, расширение libc/потоков/памяти, IPC и
песочница процессов, сетевой TLS, графический backend и файловые диалоги.
Существующий Linux-driver shim M11 не предоставляет Linux userspace ABI.
Сначала фиксировать слой платформы и тесты, затем собирать движок.
Сторонний Chromium и необходимые медиакомпоненты разрешены новым запросом
владельца; сохранять их лицензии, не перелицензировать в MIT.

Источники требований: [Chromium build](https://chromium.googlesource.com/chromium/src/+/main/docs/linux/build_instructions.md),
[sysroot](https://chromium.googlesource.com/chromium/src/+/main/docs/linux/sysroot.md),
[sandbox](https://chromium.googlesource.com/chromium/src/+/main/sandbox/linux/),
[PDF/incognito integration tests](https://chromium.googlesource.com/chromium/src/+/HEAD/chrome/browser/pdf/pdf_extension_test.cc).

Не подменять поиск результатами-заглушками; до появления HTTP/TLS/браузерного
обработчика честно показывать отсутствие провайдера и сохранять запрос.

## Формат настроек v1

Два чередующихся слота `/etc/charm-desktop.0` и `.1`, каждый 20 байт:
LE u32 magic=0x46504348, version=1, generation (1…UINT32_MAX), flags,
checksum FNV-1a первых четырёх LE слов. Flags: bit0 тени, bit1 тёплый фон,
bit2 русская раскладка универсального доступа; остальные нули.
При загрузке выбрать валидный слот с большей generation. При сохранении
писать только следующий слот с fsync; старый остаётся резервным при сбое.
Неполный/повреждённый слот игнорируется; при отсутствии валидного — defaults.
При исчерпании generation не перезаписывать файлы. Это настройка wm,
не новый интерфейс ядра и не обещание общей раскладки всех приложений.

## Следующий пакет калькулятора

Инженерный: sqrt/abs/sin/cos/tan/ln/log/exp, pi/e, числа 1e-6;
радианы, степень с целым показателем. Численные результаты ограничены
по модулю 10^100, вычисление около полюса tan возвращает ошибку.

Режим программиста: unsigned 64-bit modulo, десятичные/0x/0b числа,
арифметика, %, побитовые &, |, ^, ~, сдвиги 0…63, скобки; показывать
DEC/HEX/BIN, ошибки деления и диапазона. Это отдельная грамматика: ^ здесь XOR.
Химия: молярная масса формулы со скобками и целыми индексами, число молей
по массе; поддерживаемые элементы перечислять, неизвестные не угадывать.
Веса — округлённые CIAAW 2024, без обещания изотопной точности:
https://ciaaw.org/abridged-atomic-weights.htm.
Физика: редактируемая формула a/x и параметры с явными SI-единицами.
Модели: схема двух сопротивлений (последовательно/параллельно), напряжение,
ток и мощность; груз на пружине, статическое смещение и период малых
колебаний. Выбор элементов/соединения и изменение числовых параметров;
это первые ограниченные модели, не произвольный CAD или SPICE.
Проверять весь пакет одним прогоном: эталоны и ошибки чистой логики,
санитайзер, ввод/изменение параметров и реальные снимки QEMU.

## Возможности редактора

Нативное приложение edit: текст UTF-8 до 16383 байт, движение по символам,
строкам и мышью, выбор всего, один уровень отмены/повтора, открытие F3,
сохранение Ctrl+S и новый путь F4, автосохранение F2 после паузы ввода.
F8 переключает русский ввод. Files F6 открывает выбранный файл в редакторе.
Подсветка C/C++, Python, JavaScript/JSON, Markdown и LaTeX; Markdown имеет
простой режим просмотра, полного рендерера LaTeX пока нет.

Существующий файл сохранять только после загрузки и проверки, что его
содержимое не изменилось снаружи. Save As требует нового имени, не
перезаписывает чужой существующий файл. Предыдущая полная версия сохраняется
рядом как `.charm-backup` с fsync. Атомарной замены пока нет: нет rename ABI;
резервная копия служит восстановлением при сбое записи. При закрытии
несохранённого документа запросить Ctrl+S или явный F6 (отбросить).

## Уточнение владельца 2026-10-17: только C++

Новый код CharmOS и адаптация браузера — только C++. Эксперимент с native
Rust отменён: собственные runtime.rs, сборщик и проба удалены. Не включать
Rust ради обязательных зависимостей Chromium: JSONReader заменить настоящим
C++ парсером с контрактом upstream (Unicode, глубина, расширения и ошибки),
Rust logging bridge исключить вместе с Rust-кодом, сохранив C++ logging.
Для следующих компонентов выбирать C++ backend и проверять фактический
граф зависимостей. Нельзя заменять JSON или другие функции заглушками.
Полный C++ runtime уже прошёл browser/runtime_cpp в QEMU, включая locale,
math/fenv, потоки и UTF-8; полный браузер пока не собран, окна браузера нет.
Текущий незакоммиченный пакет содержит эти runtime-изменения и работу над base.
