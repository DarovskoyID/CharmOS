# Промпт для DeepSeek V4.1 Flash: холодный запуск браузера CharmOS

Работай в репозитории CharmOS. Владелец требует реальный холодный запуск
браузера менее 500 мс и правильный текст на google.com/example.com.
Предзагрузка, задержка доступности карточки до готовности, подмена браузера
макетом и показ пустого окна вместо готового браузера не выполняют задачу.

Сначала прочитай CLAUDE.md, plans/ROADMAP.md и docs/browser-startup-review.md.
Сохрани существующие незакоммиченные изменения: они включают проверенные
исправления другой сессии. Не делай reset/checkout всего дерева. Не меняй
публичные ABI без согласования и нормативного документа. Сторонние лицензии
и закрытые условия авторского кода сохраняются.

Если пересборка или другая нейросеть ещё работает, ограничься чтением.
Не запускай параллельные ninja/QEMU. Владелец ранее остановил другую
нейросеть и разрешил перезапуск своего тестового браузера; проверь фактические
процессы перед запуском. Не заверши посторонний процесс по одному имени.

## Что уже исправлено — не возвращать старые обходы

1. P1, user/drivers/e1000/e1000.cpp:240: idle loop видел 64-й свободный
   RX-буфер при полном 63-местном hardware ring и крутился без сна, мешая
   virtio. Проверка теперь учитывает свободные места RX/TX.
2. P1, kernel/block/block.cpp:78 и публикации CQ в блочных драйверах:
   store→load handshake требует полного барьера, release/acquire недостаточно.
3. P1, tools/chromium/platform/font_fallback_charmos.h:22:
   directory font manager не реализует character fallback. Выполняется
   перебор реальных семейств с проверкой glyph; FirstScalar:12 декодирует
   UTF-16, включая supplementary plane, и отвергает одиночные surrogate.
4. P1, tools/chromium/graphics-patches.py, clipboard_non_backed.cc:
   доступный kSelection отсутствовал в map. Ctrl+A в адресной строке
   падал на CHECK. Исправлен конструктор, проверки не отключены.
5. P1, tools/chromium/blink-patches.py и
   tools/chromium/platform/static_codec_frame_charmos.h:8: статический native
   PNG codec может не выдавать animation metadata. Адаптер выдаёт фактический
   полный статический кадр только для index=0 и isAnimated=kNo. Прежний обход
   одного DCHECK оставлял кадр неинициализированным. Не отключай картинки
   или DCHECK, не фабрикуй метаданные анимации.
6. P1/P2, user/bin/wm/wm.cpp:491,999: браузер узнаётся по opt-in начальному
   заголовку и сохранённому индексу; заголовок сайта не является identity.
   После закрытия поздний Show/Activate не должен восстанавливать окно.
7. P2, user/libc/src/stdio.cpp:711: fread читает большими порциями с сохранением
   pushback/read-ahead, EOF, ошибок и счётчика полных элементов.
8. kernel/pci/iommu.cpp:589: map_pages_at предварительно выделяет таблицы,
   публикует страницы и один раз инвалидирует домен. Изоляция DMA сохранена.
9. kernel/block/block.hpp:21: внутренний пакет 256 страниц разбивается на
   стандартные запросы по 6 сегментов, максимум 43 из 64 мест очереди.
   Нужно дождаться всех completion до DMA unmap, включая ответы с ошибкой.
10. CMakeLists.txt:13: kernel/user собираются RelWithDebInfo, с -O2 и символами.
    Предыдущий фактический -O0 не является корректной базой нового профиля.
11. tools/qemu/browser.sh:39: manual browser, без фоновой предзагрузки.

## Известные измерения и оставшаяся задача

Первоначально cold занимал 55,799 с, был также таймаут более 180 с.
После исправлений и оптимизированной сборки промежуточный cold — 4,676 с.
Разделение: чтение ELF 206508968 байт — 2164,450 мс, создание процесса —
124,134 мс, затем инициализация Chromium до первого кадра. Это промежуточный
замер до окончательного отключения предзагрузки. Актуальные числа бери из
build/browser-latency.json и build/browser-latency.serial, не подменяй их
этими числами. Повторное открытие уже занимает десятки миллисекунд и не
доказывает выполнение cold-цели.

Профилируй чтение ELF и старт Chromium раздельно. Для чтения изучи
kernel/fs/vfs.cpp::read_file, kernel/fs/cache.cpp, kernel/block/block.cpp,
kernel/proc/process.cpp:490 и драйвер virtio. Для пользовательской части
добавь измерения стадий инициализации, найди настоящие длительные операции.
Не расширяй оптимизацию на случайные компоненты без измерения. Не отключай
IOMMU, sandbox/checks, TLS, шрифты, изображения или функциональность сайтов
ради красивого результата. Если нужен новый способ загрузки исполняемых
страниц, сначала сформулируй владение страницами, права W/X, zero-fill BSS,
проверки ELF, rollback при OOM, lifetime файла, teardown и тесты изоляции;
не выпускай неподтверждённый demand paging вместо исправления.

После добавления Noto Arabic/CJK и полного отключения предзагрузки итоговый
cold составил 7365,054 мс (чтение ELF 2356,502 мс, load 116,098 мс),
warm 9,372–19,040 мс, один процесс, fatal отсутствуют. Общий harness FAIL
из-за cold>=500 мс, функциональная стабильность PASS. Увеличение времени
после добавления шрифтов требует профилирования font manager, а не удаления
нужных шрифтов. Noto Arabic/CJK уже добавлены с закреплёнными версиями/OFL;
Google и example.com визуально проверены, missing-glyph блоки устранены.

## Проверка и критерии готовности

Сборка и гостевые тесты — через WSL Ubuntu. Chromium cache монтируется
tools/chromium/with-cache.sh с CHARMOS_CACHE_IMAGE=/home/ivan/linux-cache.ext4.
Патчи vendor-кода вноси через hash-checked Python patch tables и platform
overlay, а не только в локальный cache. prepare-platform.py не запускается
одновременно с компиляцией. Графический native target требует включённого
charmos_build_graphics в args.gn; сохраняй остальные аргументы.

Запусти tools/chromium/test-browser-latency.py --samples 10 --sites google.com
example.com. Он создаёт один KVM guest, проверяет отсутствие предзагрузки,
измеряет ввод→видимый полученный кадр, проверяет close/reopen, один запуск
процесса и отсутствие fatal/restart после реального ввода адресов. Он не
доказывает загрузку сайта одним фактом сохранения screenshot: осмотри снимки.
Первая композиция рамки не равна полной отрисовке страницы; отдельно отмечай
готовность контента. Время сети/DNS/TLS не включай в локальный cold.

Общий passed обязан оставаться false при cold>=500 мс: stability_passed и
cold_target_met — разные результаты. Повтори независимые cold-прогоны;
покажи каждый, профиль сборки, конфигурацию VM, разброс и максимум. Не обещай
«всегда» по одному удачному запуску.

Обязательные регрессии по затронутым путям: host ctest; m3 user/preempt/churn;
m8 libc/spawn/threads/signals; m7 tcp_e1000; m5 iommu; m6 blk/fs1_ext2/ahci/nvme;
m10 usb_store1/graphics_runtime/window_managed. Большой дисковый тест должен
проверять полный пакет, flush и чтение обратно; восстановление драйвера —
сохранность данных и корректный повтор запроса. Не ослабляй проверки ради PASS.

Заверши отчётом: обнаруженные дефекты с P1/P2 и файлами/строками, исправления,
фактически выполненные тесты, screenshots Google/example.com, новые cold/warm
числа, оставшиеся ограничения. Если 500 мс не достигнуты, прямо назови цель
невыполненной. Не коммить и не публикуй изменения без отдельного запроса.
