# ABI: закрытая системная область и служба пакетов (v1.6)

**Статус: ЗАФИКСИРОВАН, v1.6 (2026-10-15).** Формат пакета —
package.md. Решения автора — журнал `plans/os-gui-design.md` от 2026-10-15.

## 1. Закрытая область (ядро, syscall ABI v1.6)

- Отдельный раздел GPT с типом
  `C4A12F0E-6A3B-4D52-9E3A-43484152534F` («CharmOS System Area»), файловая
  система ext2. Ядро находит его на корневом диске при загрузке и
  монтирует **вторым** экземпляром ФС, никогда — внутрь корня.
- Хендл на корень закрытой области ядро кладёт только в стартовое
  сообщение init, с новой ролью **`System` = 7** (process.md §2.1).
  init передаёт его только службе пакетов `pkgd`. Других путей к области
  нет: `..` не выходит из хендла (fs.md §1), имени для `fs_open` у неё нет.
- Обычные программы и шелл не могут ни открыть, ни перечислить её: у них
  просто нет хендла.

## 2. Консоль: чтение только у переднего плана (v1.6)

Изменение смысла `console_read` (console.md), поэтому — новая версия ABI:

- В v1.6 `console_read` и подписка `object_bind` на `Console` разрешены
  только процессам **переднего Job** (и его вложенных Job). Остальным —
  `AccessDenied`. Программа, собранная под v1.5, работает как прежде, пока
  она на переднем плане (шелл и команды так и устроены).
- Зачем: запрос подтверждения установки (§3) показывает `pkgd`, делая свой
  Job передним; программа на заднем плане не может ни перехватить ответ, ни
  «нажать» за пользователя.

## 3. Служба пакетов `pkgd`

Единственный процесс с хендлом закрытой области. Получает от init: `Root`,
`System`, `Console`, `Net`, свой `Job` (с правом `Write`), канал журнала и
канал запросов (без роли). Клиенты (шелл, позже — окно установщика M10)
получают от init копию канала запросов.

Запрос и ответ — одно сообщение канала: текст команды UTF-8; ответ —
`uint32_t status` (коды syscalls.md/process.md), затем текст.

| Запрос | Что делает |
|---|---|
| `install <путь к .cpk>` | проверяет пакет; подпись магазина → установка в закрытую область `/apps/<id>`; иначе — **подтверждение пользователя** на консоли (имя, издатель «не из магазина», список прав) и установка в `/apps/<id>` обычного корня |
| `install-url <http://…>` | то же, пакет скачивается по HTTP (RFC 9112), без TLS — только тестовый сервер M8.5 |
| `list` | установленные: id, версия, «магазин»/«не из магазина» |
| `remove <id>` | удалить (для пакетов магазина — тоже с подтверждением) |
| `run <id> [аргументы…]` | **проверка при каждом запуске**: SHA-512 исполняемого файла против подписанной таблицы (подпись таблицы тоже проверяется) → `process_spawn` с правами из манифеста; ответ — хендл `Process` в сообщении |

- Подтверждение: `pkgd` делает свой Job передним, выводит запрос и ждёт
  `y`/`n`, затем возвращает передний план. Без ответа 60 с — отказ.
- Отказ проверки (изменённый файл, испорченная подпись) — `AccessDenied`,
  запись в журнал, программа не запускается.
- Установленная программа хранит рядом с файлами `package.sig`: заголовок,
  таблицу, манифест и подпись из пакета (без данных) — по ним идёт проверка
  запуска.

## 4. Шелл

- `install <файл.cpk>` / `open <файл.cpk>` — установить (одна команда; в M10
  — двойной щелчок по файлу в окне).
- Имя команды, не найденное в `/bin`, ищется среди установленных программ и
  запускается через `pkgd run`.
