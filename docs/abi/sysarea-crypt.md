# ABI: шифрование закрытой области (формат на диске, v1)

**Статус: ЗАФИКСИРОВАН, v1 (2026-10-15).** Решения автора —
журнал `plans/os-gui-design.md` (2026-10-15): код TPM в ядре, AES-256-XTS,
печать на PCR 0–7, без TPM область не монтируется.

Граница: образ диска готовят инструменты (`tools/qemu/system.sh`,
`tools/vbox/mkimage.sh`), читает и шифрует ядро. Юзерспейс формата не видит:
pkgd работает с уже расшифрованной ФС через хендл System (pkg.md §1).

## 1. Раскладка раздела «CharmOS System Area»

| Смещение | Размер | Что |
|---|---|---|
| 0 | 4096 | заголовок (§2) |
| 4096 | до 1 МиБ | резерв (нули) |
| 1 МиБ | остаток раздела | данные: ФС (ext2), видимая ядру после расшифровки |

- Единица данных XTS — **512 байт**. Номер единицы `i` = (смещение от начала
  данных) / 512, твик — `i` в little-endian 128 бит (IEEE P1619 §5.1).
- Ключ — 64 байта: Key1 (данные) | Key2 (твик), Key1 ≠ Key2 (SP 800-38E).
- Размер данных — целое число единиц (остаток раздела отбрасывается).

## 2. Заголовок (4096 байт, little-endian)

| Смещение | Размер | Поле | Значение |
|---|---|---|---|
| 0 | 8 | `magic` | `"CHARMCRY"` |
| 8 | 2 | `version` | 1 |
| 10 | 2 | `cipher` | 1 = AES-256-XTS, 512-байтные единицы |
| 12 | 4 | `state` | 1 — данные ещё открыты (подготовлены инструментом); 2 — идёт первичное шифрование; 3 — зашифровано |
| 16 | 8 | `data_offset` | 1048576 |
| 24 | 8 | `data_units` | число единиц по 512 байт |
| 32 | 8 | `progress` | при `state` = 2: сколько единиц от начала уже зашифровано |
| 40 | 4 | `pcr_mask` | 0x000000FF (PCR 0–7) |
| 44 | 2 | `pcr_hash` | 0x000B (TPM_ALG_SHA256, банк PCR) |
| 46 | 2 | `public_size` | длина `public` |
| 48 | 2 | `private_size` | длина `private` |
| 50 | 14 | — | нули |
| 64 | `public_size` | `public` | TPM2B_PUBLIC запечатанного объекта (как отдаёт TPM2_Create) |
| 64 + `public_size` | `private_size` | `private` | TPM2B_PRIVATE запечатанного объекта |
| 4032 | 64 | `check` | SHA-512 байт 0..4031 |

- `check` неверен или `magic`/`version`/`cipher` незнакомы — область не
  монтируется.
- Инструмент пишет заголовок с `state` = 1, `public_size` = `private_size` = 0
  и открытую ФС в области данных.

## 3. Ключ в TPM

- Родитель — первичный ключ хранения в иерархии Owner, создаётся каждый раз
  заново `TPM2_CreatePrimary` по фиксированному шаблону (одинаковый шаблон —
  одинаковый ключ, ничего не хранится в NV): `TPM_ALG_SYMCIPHER`, AES-128 CFB,
  атрибуты `fixedTPM | fixedParent | sensitiveDataOrigin | userWithAuth |
  noDA | restricted | decrypt`, пустой authValue и пустой unique.
- Ключ области — запечатанный объект (`TPM_ALG_KEYEDHASH`, без схемы, 64 байта
  данных, атрибуты `fixedTPM | fixedParent | noDA`, `authPolicy` — дайджест
  `TPM2_PolicyPCR` над PCR из `pcr_mask` банка `pcr_hash`, посчитанный пробной
  сессией TPM).
- Случайный ключ — `TPM2_GetRandom` (64 байта; Key1 = Key2 — запросить снова).

## 4. Загрузка (ядро)

1. `state` = 1: получить ключ (§3), запечатать (TPM2_Create), записать
   заголовок с `state` = 2, `progress` = 0; шифровать на месте кусками,
   после каждого куска сохранять `progress`; в конце — `state` = 3.
2. `state` = 2: распечатать ключ и продолжить с `progress` (сбой питания во
   время первичного шифрования не теряет данные: единицы до `progress`
   зашифрованы, после — открыты).
3. `state` = 3: распечатать (политика PCR) и смонтировать.
4. Нет TPM, ошибка TPM, PCR не совпали — область не монтируется, в журнал
   ядра — причина (`sysarea: locked: <причина>`). Режима без шифрования нет.

## 5. Известные ограничения v1

- Ответ `TPM2_Unseal` идёт без шифрования параметров сессии: ключ виден на
  шине LPC/SPI. Защита — от кражи диска, а не от доступа к шине.
- PCR 4 содержит хеш загрузчика: обновление загрузчика или прошивки делает
  область недоступной (журнал решений: перезапечатывание — позже).
- Первичное шифрование — на загрузке и занимает время, пропорциональное
  размеру области.
