# Предложение ABI block v1.4: длинные DMA-сегменты

Статус: согласовано владельцем 2026-11-11 в чате, ответ «Да, реализуй
расширение v1.4». Действующий контракт внесён в docs/abi/block.md.

## Причина

После устранения линейного поиска кэша и увеличения окна чтения большой ELF
читается примерно за 625 мс: 399 submission batches, около 52 тысяч страниц.
В каждом стандартном запросе можно передать только 6 страниц. Поэтому 1 МиБ
распадается на 43 device requests. Пакетное уведомление virtio уже проверено
отдельно, но оно не устраняет отдельные операции устройства.

## Совместимое расширение

В `BlockHello.flags` добавить `kHelloLargeSegments = 1u << 2`.
Драйвер устанавливает флаг только если поддерживает сегменты, пересекающие
границы страниц. Структуры, смещения, размер кольца и номера операций прежние.
Без флага действуют все ограничения v1.3: каждый сегмент в одной странице.

При флаге каждый сегмент начинается по границе 512 байт, имеет ненулевую длину,
кратную 512. Сумма длин равна `blocks * block_size`, не превышает
`max_blocks * block_size`. `segment_count` остаётся 1..6. Проверяются
переполнения адреса/длины, количество сегментов, операция, размер и диапазон
LBA. Никаких адресов вне предоставленного kernel DMA mapping.

Первый поддерживающий драйвер — virtio_blk; он объявляет максимум 2048 блоков
по 512 байт (1 МиБ). Остальные драйверы не объявляют флаг и продолжают путь
v1.3. Новое ядро выбирает длинный запрос только после явного флага. Старое
ядро вправе игнорировать новый флаг и слать старые короткие запросы.

## Ядро и DMA

Объединять только страницы, которые реально образуют непрерывный DMA-диапазон.
С IOMMU существующий map_pages_at создаёт непрерывные IOVA для произвольных
физических страниц: один сегмент описывает отображённый диапазон до 1 МиБ.
Без IOMMU объединять только физически соседние страницы; иначе оставить
старое разбиение. Нельзя объявлять непрерывность произвольных физ. фреймов.

Сохранить preflight таблиц, направление DMA (Read разрешает запись устройству),
барьеры публикации и снятие отображений после всех completion. После смерти
драйвера старый домен недоступен, пакет повторяется новым драйвером по прежним
правилам; ошибка/OOM не публикует частично подготовленный запрос.

## Проверки до признания готовности

- Полный 6-МиБ внутренний пакет (шесть wire-запросов не более 1 МиБ) write/flush/read с непоследовательными физическими страницами
  при включённой IOMMU, проверкой каждого байта.
- Тот же сценарий без IOMMU — корректный fallback без ложного contiguous DMA.
- Повтор после убийства/перезапуска virtio, прежние ограничения ReadOnly и LBA.
- Неверные requests отвергаются с completion и уведомлением, без DMA.
- AHCI/NVMe/USB проходят прежние тесты без нового флага.
- Несколько независимых cold-прогонов с прежними шрифтами/страницей, без
  предзагрузки; cold и готовность контента измеряются отдельно.

Это изменение уменьшает количество I/O, но само по себе не доказывает
достижение 500 мс: отдельно остаются ELF loading и инициализация Chromium.

Реализация ядра ограничивает внутренний пакет 1536 страницами (6 МиБ).
Это не размер одного wire-запроса: negotiated max_blocks применяется к
каждому запросу отдельно. Без IOMMU пакет разбивается на прежние подзапросы.
