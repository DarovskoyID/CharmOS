# ABI: системные вызовы

**Статус: ЗАФИКСИРОВАН, версия 1.0 (2026-10-14).** Дальше меняется только по
правилам §6.

Код: `include/abi/syscall.hpp` (номера, коды ошибок, константы) — единственный
заголовок, общий для ядра и пользовательского рантайма.

## 1. Принципы

- Вызов — инструкция `SYSCALL` (x86-64). Других входов в ядро из ring 3 нет.
- Каждый вызов возвращает **статус**. Значения — через регистр (одно 64-битное)
  или через указатели на память процесса.
- Ресурсы адресуются **хендлами** (M4: капабилити с правами). В v1.0 хендлов
  ещё нет, но место в ABI под них зарезервировано: тип, недействительное
  значение, коды ошибок.
- Ядро никогда не доверяет аргументам: любой указатель проверяется и
  копируется с перехватом ошибок страниц; плохой указатель — ошибка
  `BadAddress`, а не падение ядра.
- Номер вызова, однажды выданный, никогда не переиспользуется.

## 2. Соглашение о вызове

| Что | Регистр |
|---|---|
| Номер вызова | `RAX` |
| Аргументы 1–6 | `RDI`, `RSI`, `RDX`, `R10`, `R8`, `R9` |
| Статус (результат) | `RAX` |
| Значение (если есть) | `RDX` |
| Портятся | `RCX`, `R11` (их использует сама инструкция `SYSCALL`), `RAX`, `RDX` |
| Сохраняются | все остальные регистры общего назначения, `RSP`, флаги (кроме сказанного ниже), состояние x87/SSE |

`R10` вместо `RCX` для 4-го аргумента: `SYSCALL` пишет в `RCX` адрес возврата
(SDM Vol. 2B, SYSCALL). Это та же раскладка, что у System V для функций,
кроме 4-го аргумента, — обёртки в рантайме тривиальны.

Флаги: ядро возвращает `RFLAGS` пользователя без изменений, кроме `RF`, и
принудительно ставит `IF=1`. Стек пользователя ядро не использует и не
трогает.

## 3. Статусы

`RAX` после вызова — `uint64_t` статус. `0` — успех, остальное — ошибка:

| Код | Имя | Смысл |
|---|---|---|
| 0 | `Ok` | успех |
| 1 | `NotSupported` | неизвестный номер вызова или операция не поддерживается |
| 2 | `InvalidArgs` | аргумент вне допустимых значений |
| 3 | `BadAddress` | указатель вне пользовательской половины или страница не отображена |
| 4 | `NoMemory` | ядру не хватило памяти |
| 5 | `BadHandle` | хендл недействителен (M4) |
| 6 | `AccessDenied` | у хендла нет нужного права (M4) |
| 7 | `WrongType` | хендл не того типа объекта (M4) |
| 8 | `WouldBlock` | операция заблокировалась бы, а просили не ждать |
| 9 | `TimedOut` | истёк срок ожидания |
| 10 | `PeerClosed` | другая сторона закрыла канал (M4) |
| 11 | `OutOfRange` | значение или смещение за границей объекта |
| 12 | `BufferTooSmall` | буфер вызывающего мал; нужный размер — в `RDX` |
| 13 | `Busy` | ресурс занят |

Новые коды добавляются только в минорных версиях. Пользовательский код обязан
считать **любой** ненулевой неизвестный ему код ошибкой.

## 4. Типы

- Время — `uint64_t` наносекунды монотонных часов (отсчёт от загрузки).
  Сроки ожидания — абсолютные (deadline), а не интервалы: повтор вызова после
  прерывания не удлиняет ожидание. `UINT64_MAX` — ждать бесконечно.
- Хендл — `uint32_t`; `0` — недействительный хендл (M4).
- Указатель + длина — всегда парой; длина в байтах, `uint64_t`.
- Пользовательская половина адресного пространства: `[0, 0x0000800000000000)`.

## 5. Вызовы v1.0

| № | Имя | Аргументы | `RDX` при успехе | Ошибки |
|---|---|---|---|---|
| 0 | `abi_version` | — | `(major << 16) \| minor` | — |
| 1 | `debug_write` | `const char* buf, uint64_t len` | записано байт | `BadAddress`, `InvalidArgs` (len > 4096) |
| 2 | `process_exit` | `int64_t code` | не возвращается | — |
| 3 | `thread_yield` | — | — | — |
| 4 | `clock_monotonic` | — | текущее время, нс | — |
| 5 | `nanosleep` | `uint64_t deadline_ns` | — | — |

`debug_write` пишет в журнал ядра (serial) с префиксом процесса; предназначен
для отладки и тестов, но, как и всё здесь, стабилен.

`process_exit` завершает процесс целиком (в v1.0 у процесса один поток; с v1.5 потоков может быть несколько — docs/abi/process.md §4).

## 6. Версионирование

- `abi_version` возвращает версию ABI ядра. Программа, собранная под `1.N`,
  работает на ядре `1.M` при `M ≥ N`.
- **Минорная версия** (`1.N → 1.N+1`): новые вызовы с новыми номерами, новые
  коды ошибок, новые флаги в ранее зарезервированных битах. Ничего не
  удаляется и не меняет смысл.
- **Мажорная версия**: любое несовместимое изменение. Старое поведение
  продолжает обслуживаться под старыми номерами, пока жив хоть один
  поддерживаемый мажор.
- Неизвестный номер → `NotSupported`, никогда не паника.

## 7. Начальное состояние процесса

При первом входе в ring 3 (точка входа ELF, `e_entry`):

| Что | Значение |
|---|---|
| `RSP` | вершина стека, выровнена на 16 (как перед `call`, psABI §3.4.1) |
| `RDI` | `0` — зарезервировано под стартовый хендл (M4) |
| Остальные GPR | `0` |
| `RFLAGS` | `IF=1`, остальное по умолчанию |
| x87/SSE | после `FNINIT`; `MXCSR = 0x1F80` (psABI §3.2.3) |
| `FS`/`GS` база | `0` |

Аргументов командной строки и окружения в v1.0 нет.

## 8. Решения при фиксации v1.0

- Результат: статус в `RAX`, одно значение в `RDX`. Ошибка и результат не
  смешиваются; частые вызовы не пишут в память процесса.
- Сроки — абсолютные deadline по монотонным часам: повтор вызова не удлиняет
  ожидание.
