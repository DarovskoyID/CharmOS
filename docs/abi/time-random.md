# ABI: время UTC и аппаратная случайность

Версия syscall ABI 1.12, boot ABI 1.1 (2026-10-17). Необходимые зависимости
запрошенного владельцем нативного Chromium/HTTPS; решение реализации в рамках
поручения продолжать самостоятельно. Существующие номера/смыслы не меняются.

## 1. ClockRealtime = 70

Аргументов нет. При Ok значение RDX — наносекунды UTC от 1970-01-01.
При отсутствии корректного времени прошивки — NotSupported, RDX=0.
ClockMonotonic (4) остаётся независимым источником сроков ожидания.
Время UTC привязано к снимку UEFI GetTime и калиброванному TSC; разрешение
и начальная точность ограничены прошивкой, синхронизации NTP пока нет.
Изменять время этим вызовом нельзя. Переполнение возвращает OutOfRange.

## 2. RandomRead = 71

RDI — адрес буфера, RSI — длина 0…256, RDX — flags. Единственный флаг
bit0 NonBlock; остальные InvalidArgs. При Ok RDX — вся запрошенная длина.
При длине 0 буфер не используется, источник не требуется; flags проверяются.
Источники: RDRAND с CPUID.01H:ECX[30] и проверкой CF, до 10 попыток на
64-битное слово; при неудаче/отсутствии — TPM2_GetRandom под блокирующим
mutex. Публиковать частичный аппаратный результат при ошибке нельзя.
TPM-снимки/ключи закрытой области не выдаются; только новые случайные байты.
NonBlock использует RDRAND; если доступен только TPM — WouldBlock.
Нет обоих источников — NotSupported, временная неготовность RDRAND —
WouldBlock, сбой TPM — IoError, неверный буфер — BadAddress.

Вызов доступен обычным процессам без отдельной capability: он не изменяет
глобальных настроек и не выдаёт секретов других процессов. Максимум 256 байт
ограничивает время аппаратной операции. Это аппаратный источник для seed
пользовательского TLS DRBG, не новая самодельная криптографическая PRNG.
Псевдослучайный fallback из времени/адресов/счётчиков запрещён.
TPM-доступ всех runtime клиентов сериализуется общим tpm::runtime_mutex,
включая разблокировку закрытой области: драйверы уже работают при mount.
Только первоначальный init TPM выполняется до запуска планировщика/процессов.

Источники: docs/specs/intel-sdm-vol2.pdf, RDRAND и CPUID leaf 1;
docs/specs/tpm2-part3-commands.pdf, TPM2_GetRandom.

## 3. libc

clock_gettime(CLOCK_REALTIME) и time() используют ClockRealtime; MONOTONIC
сохраняет прежнюю семантику. Неизвестный clockid — EINVAL, null timespec —
EFAULT. При отсутствии RTC time() возвращает -1 с errno, не uptime.
getrandom() циклически читает до 256 байт, возвращает успешный префикс при
поздней ошибке; flags только 0/GRND_NONBLOCK. getentropy() требует ≤256
и возвращает 0 после полного чтения, при превышении EIO.

## 4. Проверки пакета

Хост: календарь, високосные века, границы суток/часового пояса/переполнения,
совместимость BootInfo 1.0. QEMU: фиксированный RTC, рост обоих часов,
неизвестные clockid/flags/плохой указатель, параллельные RNG-клиенты,
источник RDRAND, TPM fallback и отсутствие источника. Функциональные проверки
байтов не являются доказательством качества энтропии или проверкой железа.
