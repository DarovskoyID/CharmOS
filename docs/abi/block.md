# ABI: блочные драйверы (syscall ABI v1.3)

**Статус: ЗАФИКСИРОВАН, v1.3 (2026-10-14).** Минорное расширение v1.2
(docs/abi/driver.md): старое не меняется. Основа — решения автора от
2026-10-14: запросы идут через кольцо в VMO с уведомлениями через канал и
порт; страницы page cache ядро на время запроса отображает в домен IOMMU
драйвера (без копирования).

## 1. Модель

- Блочный драйвер — драйвер класса `block` (манифест: `class = "block"`,
  docs/abi/driver.md §7). Он обслуживает одно устройство и один его диск
  (namespace NVMe, порт AHCI — каждый отдельным `Device`/запуском — пока нет;
  в v1.3 один драйвер = один диск).
- Ядро — единственный клиент диска: блочный слой, page cache, ФС в ядре.
- Данные не копируются: в запросе — адреса для устройства (IOVA) страниц
  ядра, отображённых в домен драйвера только на время запроса. Драйвер к этим
  страницам из процессора доступа не имеет.

## 2. Рукопожатие (по стартовому каналу, после `"device"`)

1. Драйвер инициализирует устройство и шлёт ядру сообщение `BlockHello`
   (§5.1), без хендлов.
2. Ядро отвечает сообщением `"ring"` с двумя хендлами: VMO кольца (права
   `Read | Write | Map`) и концом канала уведомлений (§4).
3. С этого момента ядро шлёт запросы. Ответ ядра `"reject"` (без хендлов) —
   параметры диска неприемлемы, драйвер завершается.

## 3. Кольцо (VMO, 4 страницы)

| Смещение | Что |
|---|---|
| 0 | `RingHeader` (§5.2) |
| 4096 | `Request sq[64]`, по 128 байт — очередь запросов (пишет ядро) |
| 12288 | `Completion cq[64]`, по 16 байт — очередь ответов (пишет драйвер) |

- Индексы — свободно растущие `uint32_t`, позиция = индекс mod 64. Запись
  элемента — затем индекс с семантикой release; чтение индекса — acquire,
  затем элемент.
- `sq_tail` двигает ядро, `sq_head` — драйвер (взял запрос). `cq_tail` —
  драйвер, `cq_head` — ядро.
- Запросов в работе не больше 64; ответ может прийти в любом порядке, связь —
  по `id`.

## 4. Уведомления

Канал уведомлений: один конец у ядра, другой у драйвера. Сообщение —
0 байт, без хендлов («звонок»).

- Ядро звонит, если после добавления запросов в header стоит
  `driver_wants_kick = 1`. Драйвер ставит флаг перед тем, как заснуть на
  порту, и снова проверяет `sq` (иначе пропуск звонка).
- Драйвер звонит после добавления ответов, если `kernel_wants_kick = 1`.
- Драйвер ждёт звонки, привязав свой конец к порту (`object_bind`) вместе с
  прерыванием устройства.

## 5. Структуры (все little-endian, `static_assert` в include/abi/block.hpp)

### 5.1. `BlockHello` (32 байта)

| Смещение | Поле | |
|---|---|---|
| 0 | `char magic[4]` | `"blk1"` |
| 4 | `uint32_t block_size` | 512 или 4096 |
| 8 | `uint64_t block_count` | |
| 16 | `uint32_t max_blocks` | наибольший запрос в блоках (≥ 8) |
| 20 | `uint32_t flags` | бит 0 — `ReadOnly`, бит 1 — `Flush` поддержан |
| 24 | `uint64_t reserved` | 0 |

### 5.2. `RingHeader` (64 байта)

| Смещение | Поле |
|---|---|
| 0 | `uint32_t sq_head` |
| 4 | `uint32_t sq_tail` |
| 8 | `uint32_t cq_head` |
| 12 | `uint32_t cq_tail` |
| 16 | `uint32_t driver_wants_kick` |
| 20 | `uint32_t kernel_wants_kick` |
| 24 | `uint8_t reserved[40]` |

### 5.3. `Request` (128 байт)

| Смещение | Поле | |
|---|---|---|
| 0 | `uint64_t id` | ядро, возвращается в ответе |
| 8 | `uint32_t op` | 1 Read, 2 Write, 3 Flush |
| 12 | `uint32_t segment_count` | 0 для Flush, иначе 1..6 |
| 16 | `uint64_t lba` | в блоках `block_size` |
| 24 | `uint32_t blocks` | сумма длин сегментов / `block_size` |
| 28 | `uint32_t reserved` | 0 |
| 32 | `Segment segments[6]` | по 16 байт: `uint64_t iova; uint32_t bytes; uint32_t reserved` |

Сегменты выровнены по 512 байт и кратны 512; каждый внутри одной страницы
4 КиБ.

### 5.4. `Completion` (16 байт)

| Смещение | Поле | |
|---|---|---|
| 0 | `uint64_t id` | |
| 8 | `int32_t status` | 0 — успех, иначе код `Status` (docs/abi/syscalls.md §4): `IoError`, `InvalidArgs`, `NotSupported` |
| 12 | `uint32_t reserved` | 0 |

## 6. Падение драйвера

Отображения страниц в старом домене снимаются вместе с ним. Незавершённые
запросы ядро ставит заново в кольцо нового запуска драйвера (чтение и запись
целых блоков идемпотентны; Flush повторяется). Если драйвер исчерпал
перезапуски, все запросы завершаются `IoError`, диск помечается неисправным.

## 7. Новое в v1.3 для драйверов

- Новые коды статуса (docs/abi/syscalls.md §4) — в docs/abi/fs.md §6:
  `IoError = 14` и другие.
- Новых системных вызовов для блочного протокола нет: VMO, каналы, порты —
  из v1.1–v1.2.
