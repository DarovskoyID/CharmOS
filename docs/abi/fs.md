# ABI: файлы и каталоги (syscall ABI v1.3)

**Статус: ЗАФИКСИРОВАН, v1.3 (2026-10-14).** Минорное расширение v1.2:
новые объекты, вызовы и коды статуса, старое не меняется. ФС — в ядре
(журнал решений: гибридное ядро).

## 1. Модель

- Файл и каталог — объекты ядра, доступ к ним только по хендлам
  (docs/abi/ipc.md). Глобального пространства имён у процесса нет: путь
  всегда отсчитывается от хендла каталога.
- Хендл каталога ограничивает доступ его поддеревом: компонента `..`
  запрещена (`InvalidArgs`), символьных ссылок в v1.3 нет. Отдать процессу
  каталог — значит отдать ровно это поддерево.
- Права хендла: `Read` — читать файл / перечислять каталог и открывать в нём
  только на чтение; `Write` — писать файл / создавать и удалять в каталоге.
  Открытое через каталог не получает прав больше, чем у каталога.
- Позиции в файле у хендла нет: чтение и запись — с явным смещением
  (как pread/pwrite). Это делает хендл безопасным для передачи и общего
  использования.

## 2. Откуда берётся корень

Процесс, которому ядро даёт доступ к ФС, получает в стартовом канале
сообщение `"root"` с одним хендлом каталога (корень смонтированной ФС, права
`Duplicate | Transfer | Read | Write`). Кому его давать — решает ядро (в M6:
тестовые программы по `ktest`; позже — init).

## 3. Монтирование (ядро, не ABI)

Корень выбирается командной строкой: `root=<диск>p<раздел>` (диски
нумеруются в порядке запуска блочных драйверов: `disk0`, `disk1`…), разделы —
по GPT (UEFI 2.11 §5.3). ФС определяется по содержимому: FAT32 или ext2.
Ниже корня другие ФС в v1.3 не монтируются.

## 4. Вызовы v1.3

| № | Имя | Аргументы | `RDX` при успехе |
|---|---|---|---|
| 23 | `fs_open` | `dir, const char* path, len, flags` | хендл файла или каталога |
| 24 | `file_read` | `file, void* buf, len, offset` | прочитано байт (0 — конец файла) |
| 25 | `file_write` | `file, const void* buf, len, offset` | записано байт |
| 26 | `file_sync` | `file` | — |
| 27 | `fs_stat` | `h, Stat* out` | — |
| 28 | `dir_read` | `dir, void* buf, cap, uint64_t cookie` | новый cookie (§4.2) |
| 29 | `fs_unlink` | `dir, const char* path, len` | — |
| 30 | `file_resize` | `file, uint64_t size` | — |

- `path` — UTF-8, разделитель `/`, без начального `/`, компоненты непустые,
  до 255 байт; путь целиком до 4096 байт. Пустой путь — сам `dir`.
- `flags` для `fs_open`: бит 0 `Write` (нужно право `Write` у `dir`),
  бит 1 `Create` (создать файл, если нет), бит 2 `Exclusive` (с `Create`:
  ошибка `AlreadyExists`, если есть), бит 3 `Truncate`, бит 4 `Directory`
  (ожидается каталог; с `Create` — создать каталог).
- `file_write` за концом файла расширяет его (дыра читается нулями).
- `file_sync` возвращается, когда данные и метаданные файла на диске
  (Flush устройства выполнен).
- `len` у чтения/записи — до 1 МиБ за вызов.

### 4.1. `Stat` (32 байта)

| Смещение | Поле | |
|---|---|---|
| 0 | `uint64_t size` | байт |
| 8 | `uint32_t type` | 1 файл, 2 каталог |
| 12 | `uint32_t reserved` | 0 |
| 16 | `uint64_t mtime_ns` | 0, если ФС не хранит |
| 24 | `uint64_t reserved2` | 0 |

### 4.2. `dir_read`

Записи `DirEntry` пишутся в `buf` подряд: `uint16_t record_len` (кратно 8),
`uint8_t type`, `uint8_t name_len`, затем имя (без нуля), выравнивание
нулями. Начало — `cookie = 0`. Результат в `RDX`: новый cookie для
следующего вызова; число записей узнаётся проходом по `record_len`; конец
каталога — 0 записей (пустой ответ). Ни одна запись не влезла —
`BufferTooSmall`. Записей `.` и `..` нет.

## 5. Права и ошибки

| Ситуация | Статус |
|---|---|
| нет такого пути (и нет `Create`) | `NotFound` |
| файл уже есть при `Exclusive` | `AlreadyExists` |
| ждали каталог, а это файл (или наоборот) | `WrongType` |
| удаление непустого каталога | `Busy` |
| ошибка устройства | `IoError` |
| нет места | `NoSpace` |
| ФС только для чтения | `AccessDenied` |

## 7. Что не входит в v1.3

Символьные и жёсткие ссылки, права доступа UNIX и владельцы, переименование,
отображение файлов в память, блокировки, уведомления об изменениях,
монтирование ниже корня. Всё — новыми минорными версиями.

## 8. Уточнения при реализации (2026-10-14)

Не меняют смысла v1.3, снимают неоднозначности текста выше.

- `dir_read` (§4.2): после последней записи ядро пишет `record_len = 0`
  (2 байта), если в буфере есть место; разбор идёт до `record_len = 0` или
  до конца буфера. Пустой ответ (конец каталога) — первым идёт
  `record_len = 0`; `cap` меньше 2 — `BufferTooSmall`.
- `fs_unlink` файла или каталога, на который открыт хендл (в любом
  процессе), — `Busy`: узел нельзя удалить из-под открытых хендлов.
- `fs_open` без бита `Directory` на каталог и с ним на файл — `WrongType`;
  пустой путь — сам `dir` (тогда нужен бит `Directory`).
- `Truncate` без `Write`, `Exclusive` без `Create`, `Truncate` с
  `Directory` — `InvalidArgs`.
- `file_sync` сбрасывает всю ФС (метаданные, кэш, кэш устройства), а не
  только этот файл — это допустимо по §4 («данные и метаданные файла на
  диске»).
